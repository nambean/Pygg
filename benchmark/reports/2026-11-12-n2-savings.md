# N2: what routing saves on harder coding tasks, 2026-11-12

> **Status:** Record · **approved for publication by the owner on 2026-11-12** · ROADMAP N2 · run 2026-11-11 to 2026-11-12 · earlier pass: [C3 first pass](2026-11-11-c3-first-pass.md) · order: [ROADMAP](../../docs/ROADMAP.md)

**In one line:** on 12 harder coding tasks, each run three times by the same agent, sending the work through Pygg to Claude Haiku 5.5 instead of Claude Sonnet 5.5 cost **88% less per solved task (95% CI 87% to 90%)**, and solved 36 of 36 against Sonnet's 34 of 36. Routing to a subscription model solved 35 of 36 with no metered money, but used the subscription's quota and took about four times as long.

## Results for readers

Same agent (OpenCode 1.18.4), same tasks, same checks; only the model behind it changes. A task counts as solved only when its own tests pass and the agent left the tests untouched.

| How the agent's requests were routed | Solved | Money per solved task | Against pinned Sonnet | Median time per task |
| --- | --- | --- | --- | --- |
| Pinned to Claude Sonnet 5.5 (the baseline) | 34/36 (94%) | $0.114 | — | 38 s |
| Through Pygg to Claude Haiku 5.5 | **36/36 (100%)** | **$0.013** | **88% less** (87% to 90%) | 40 s |
| Pygg `auto`, which chose a Qwen subscription model | 35/36 (97%) | no metered money; 329 requests of subscription quota | not comparable: the quota is paid for monthly | 153 s |
| Pygg cascade: a local 8B model first, then Haiku, then Sonnet | **36/36 (100%)** | $0.014 | **88% less** (86% to 90%) | 165 s |
| Pygg cascade: a free hosted model first, then Qwen, then Haiku, then Sonnet | **36/36 (100%)** | $0.003 metered, plus 207 requests of Qwen's subscription quota | 97% less metered money, but not comparable: most of the work was paid for by the subscription | 451 s, of which about 300 s waiting for the free model |
| OpenCode's free model alone | 0/36 | $0 | — | 302 s (time limit) |

Percent ranges are 95% confidence intervals from a bootstrap over the 12 tasks, paired so that both arms see the same draw of tasks. Pass-rate intervals (Wilson): 34/36 is 82% to 98%, 35/36 is 86% to 100%, 36/36 is 90% to 100%. The intervals overlap, so **this run does not show that Haiku is better than Sonnet**; it shows that on these tasks Haiku was not measurably worse while costing about a ninth as much.

## What was run

- **Tasks.** The 12 `hard-*` cases in [`benchmark/cases`](../cases): 3 bug fixes (a concurrency limit in an async pool, cart totals against written rules across three files, an off-by-one in a sliding window), 8 features (expression evaluator, line diff, next cron time, JSON Patch, semver ranges, glob matching, INI parsing, text tables) and one three-file refactor; 8 rated high complexity, 4 medium. Passing solutions added 20 to 211 lines. Node only. Each fixture was checked to fail as given and to pass with a reference solution kept outside the repository. The test files are protected: an attempt that changes one fails.
- **Repeats.** Every task three times per arm: 36 runs per arm.
- **Agent.** OpenCode 1.18.4 in headless mode (`opencode run --format json`), one Git worktree per attempt, driven by Pygg's task engine (`bench --engine opencode`), so a cascade hands the failed check's output to the next step exactly as the app does.
- **Time limit per attempt.** 15 minutes for Sonnet, Haiku and `auto`, which ran first. The free model's arm and the free-first cascade were then run with 5 minutes, after the free model's first attempts reached the limit without answering; the local-first cascade with 10, because the local model is slower. No Sonnet or Haiku attempt came near its limit (the longest took 125 s).
- **Routing.** Paid and subscription models were reached through a Pygg gateway (headless, on a scratch store) on its Anthropic-format surface. Every attempt carried its own session key (`PYGG_ATTEMPT_ID`), and its cost is what the gateway's ledger recorded for that attempt. OpenCode's free model went to OpenCode's own service directly.
- **Models.** Claude Sonnet 5.5 and Claude Haiku 5.5 (Anthropic API); `qwen3.8-flash` on Alibaba Model Studio's token plan (a monthly subscription); `qwen3:8b` on Ollama, in Docker on an RTX 3060 with 12 GB (context 32,768 tokens); `opencode/deepseek-v4.1-flash-free`.
- **Prices.** Anthropic list prices, as in the [first pass](2026-11-11-c3-first-pass.md#setup): Sonnet 5.5 $2 / $10 per million input / output tokens, cache reads $0.20; Haiku 5.5 $0.10 / $0.50, with cache reads priced as input because no cache-read price was stated, so Haiku's figures are an upper bound. Cache writes at 1.25 times input. Figures are list-price estimates from token counts, not provider invoices.
- **Spending limit.** The gateway client had a strict monthly limit, so every request was held at the most it could cost before it was sent.

## What the numbers say

- **The saving comes from not paying a premium model for work a cheaper one does.** Sonnet and Haiku used similar amounts of context (Haiku wrote more output), and Haiku's list price is a twentieth of Sonnet's per token, which on these tasks became 88% less money per solved task.
- **The tasks separate the models now.** The first pass's 24 tasks were passed by every model. Here the local 8B model solved 1 of 36 on its own, Sonnet missed `hard-cart-rules` twice (both times it ended without changing a file), and `auto`'s Qwen model timed out once on `hard-semver-range`.
- **A local model on a mid-range GPU did not pay for itself on these tasks.** `qwen3:8b` solved 1 of 36; the other 35 went on to Haiku. The cascade cost what Haiku alone cost (the difference is within the interval) and took about four times as long, because every task first spent a median of 2 minutes on the local model. A local first step is worth it only where the local model solves a real share of the tasks: easier work, or a larger model on a larger GPU.
- **A subscription model is not free.** `auto` chose Qwen's token plan because its marginal cost is zero, and it solved 35 of 36. It used 329 requests of a monthly quota and was the slowest arm with a single model. Whether that is cheaper than Haiku depends on what the plan costs and what else uses its quota, which this run does not measure.
- **A step that does not answer costs time, not money.** OpenCode's free model did not answer at all during this run: all 36 runs reached the 5-minute limit with no output token, and a one-line prompt sent directly at the end of the run also got no answer within 90 s. In the first pass, the day before, the same model solved 24 of 24 easier tasks. So this run says nothing about the free model's ability, only that a free service can be unavailable. In the free-first cascade, every task first waited the full 5 minutes. Then Qwen's subscription model solved 30 of 36 and Haiku the other 6, so that arm measures a dead first step followed by a subscription, not a free model. **Product change made after this run:** the task engine now skips a step whose agent and model timed out twice in a row within 30 minutes without answering, unless it is the last step left (`tasks.rs`, test `a_step_that_twice_timed_out_without_answering_is_skipped_unless_it_is_the_last`). This run does not measure that change.

## What this run cannot claim

- **Savings on your work.** These are 12 small, self-contained Node tasks with deterministic tests. Larger repositories, other languages, vaguer requests and tasks without tests may favour the premium model more.
- **That Haiku is better than Sonnet.** Its higher pass rate is within the intervals.
- **Provider bills.** Money is estimated from token counts at list prices; Haiku's cache reads are priced as input, so its figures are an upper bound. Batch or negotiated prices are not considered.
- **Other agents.** Only OpenCode was used. Claude Code, Codex and others send different prompts and use context differently.
- **The free model's quality**, since it did not answer; and the subscription's real cost, since a monthly plan has no price per request.
- **Variance across days.** All runs took place over about 14 hours on 2026-11-11 and 2026-11-12; provider load at other times may differ.

## Spend

Metered money in N2 (gateway ledger, list prices): **$4.98**. Sonnet's arm cost $3.88. Haiku cost $1.10, spread across the Haiku arm, the two cascades and earlier trials. Together with C1's $0.30, C3's $2.14 and N8's live check (under $0.001), that is about **$7.42 of the $20** benchmark budget (ADR-028). Qwen's requests were quota and Ollama's were local.

## Reproducing

1. A gateway store with the Anthropic, Qwen (token plan, billing subscription) and Ollama connections, the prices above (`gateway model … --price-in --price-out --price-cached --price-cache-write --price-source`), and a strict client: `gateway create-client --name opencode --monthly-usd 17.5`, `gateway client --name opencode --strict yes`. Serve it with `gateway --db STORE serve --port 8799`.
2. OpenCode configured with a provider `pygg` that uses `@ai-sdk/anthropic` with `baseURL` `http://127.0.0.1:8799/v1`, the client's token, and the header `x-smarttaskrouter-session: {env:PYGG_ATTEMPT_ID}` ([benchmark README](../README.md#through-the-gateway)).
3. One run per arm, from `apps/desktop/src-tauri`:

   ```powershell
   bench --cases <folder with the 12 hard-* cases> --out <results> --engine opencode --repeat 3 `
     --gateway-db STORE --agent-timeout 900 `
     --rung T2=pygg/anthropic/claude-haiku-5-5 --mode single --budget-usd 4
   ```

   Other arms change the `--rung` list and `--mode`: `T4=pygg/anthropic/claude-sonnet-5-5`; `T1=pygg/auto`; `--mode cascade` with `T0=pygg/ollama/qwen3:8b T2=… T4=…` (`--agent-timeout 600 --allow-unknown yes`); `--mode cascade` with `T0=opencode/deepseek-v4.1-flash-free T1=pygg/qwen-alibaba-model-studio/qwen3.8-flash T2=… T4=…` (`--agent-timeout 300 --allow-unknown yes`). `--allow-unknown yes` lets a run go on after an attempt whose money cost could not be read, which a step that bypasses the gateway, such as OpenCode's free model, always is.
4. `python scripts/bench-report.py <results>/*.jsonl --baseline sonnet`.

**Raw results** are in [`benchmark/results/2026-11-12-n2/`](../results/2026-11-12-n2): one file per arm, one JSON line per run, holding every attempt's checks, tokens and ledger figures, with a `SHA256SUMS` file. Local machine paths in check output were replaced with `<local path>`, and the files were scanned for keys and tokens before they were committed. To reproduce the table above, run `python scripts/bench-report.py benchmark/results/2026-11-12-n2/*.jsonl --baseline sonnet`.
