# What Pygg changes: published benchmarks

> **Status:** Current · every published benchmark in one table, each figure linked to its report, and Pygg next to other gateways · reviewed 2026-11-20

Runs use real agents, real models and checks the agent cannot edit; a fault-injecting fake provider is used where a fault has to repeat. Read a row's report (method, raw results, what it left out) before quoting a number; the harness is in [benchmark/README.md](../benchmark/README.md).

**Spend** (budget: [ADR-028](DECISIONS.md#adr-028--mit-licence-a-20-benchmark-budget-and-no-auto-chat)): about $16.7 for the runs to 2026-11-16, $16.10 for the overnight run of 2026-11-20, $7.21 for the hard-case repeat that day, $0 for the comparison runs.

## Where Pygg is worse

- **Throughput:** 230 vs LiteLLM's [published](https://docs.litellm.ai/docs/benchmarks) 1,170 requests/s (D); Pygg is for one person's tools, not a team's traffic.
- **Provider fails after receiving the request:** 96% / 0% served by default vs LiteLLM's 100% (three attempts each, M). A 5xx retry can be turned on per API key (Endpoint → API Keys → Limits); a dropped connection is never retried.
- **Provider hangs:** Pygg waits up to 10 minutes for an answer to start, with no fallback on a timeout. LiteLLM also waits by default; with a 30 s timeout it fell back after about 91 s, leaving three abandoned attempts at the provider (M).
- **Stream cut mid-answer:** cannot be continued on another model; LiteLLM [documents](https://docs.litellm.ai/docs/router/learn/reliability) opt-in continuation for plain text (D).
- **Prompt caching for Chat Completions clients:** LiteLLM matches Pygg once configured (M).
- **Web sessions are slow by design:** a person's pace per site, short prompts, no tools ([the guard](PROVIDERS.md#the-guard)).
- **`auto/cheap` can pick a model too weak for the task** (2 / 6 on the real repository); `auto` with a tier floor is the default for agents.
- **Platforms:** desktop app Windows x64 only; command line and headless gateway published for Windows, Linux and macOS, not yet run on a Mac.

## What Pygg does not claim

- **No "60–95% fewer tokens".** An [independent replay](https://codepointer.dev/p/cutting-llm-token-costs-with-rtk) of 500 real Claude Code sessions found 3.7% for compression tools; Pygg saves through the provider's cache, cheaper models you choose and visible routing (ADR-036 in [DECISIONS.md](DECISIONS.md)).
- **Not a quality benchmark.** Pass rates come from each case's own checks on a handful of tasks: an approach did not break the work, not that one model is better.
- **Not a provider bill.** Costs are each gateway's ledger at list prices.
- **Not a ranking of other projects.** D rows are what each project says about itself on one day; behaviour can differ and projects change.
