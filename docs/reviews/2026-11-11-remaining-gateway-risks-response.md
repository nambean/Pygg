# Response to the follow-up review: remaining gateway risks, 2026-11-11

Responds to [Remaining Gateway Risks](2026-11-11-remaining-gateway-risks.md). Each finding was checked against the source before it was decided. Every accepted change is in the commit that adds this note, with the tests named below. `cargo test`: 87 passed, 1 ignored (84 before); three new end-to-end tests, and four existing ones now opt in to retries explicitly.

**Result:** FR-01, FR-02, FR-03 and FR-04 are accepted. Two parts are deferred, with reasons below. The review's three objections to the earlier response (privacy, paid retries, admission while degraded) were right: in each case the earlier answer described a property the code did not enforce.

### Deferred, and why

- **FR-01, provider data-use terms per preset (GW-10).** A "sensitive" profile that fails closed on *unknown terms* needs terms with a source and a date for each provider and tier. Until those exist, every preset's terms are unknown, so such a profile would refuse everything. The allowlist is the workable control today: the user names the connections whose terms they have checked. Terms per preset stay planned with P0-5, where they also become an Auto filter.
- **FR-03, reconciliation against the provider's own usage.** No preset has a documented per-request usage lookup the gateway could call afterwards. Anthropic's and OpenAI's usage reports are aggregated by time bucket and model, not per request. An interrupted or unknown attempt therefore stays Unknown, with its held amount at risk. It is never given an invented actual cost. If a provider offers a per-request lookup later, it belongs in that provider's adapter.

### What the tests do not cover

The review listed disk-full, lock contention and two gateway processes among its cases. The tests use `PRAGMA query_only` to make the store refuse writes at chosen moments. That exercises the same paths as any write failure (journal before sending, settlement after the answer, recovery), but not each SQLite error code. Two processes are covered by the design rather than by a test: both write through `BEGIN IMMEDIATE` with a 5 s busy timeout, startup recovery only touches journal entries older than an hour, and each settlement checks that its journal entry still exists. A crash while streaming leaves a journal entry, which becomes an interrupted entry at the next start (`an_attempt_never_settled_becomes_an_interrupted_entry`).
