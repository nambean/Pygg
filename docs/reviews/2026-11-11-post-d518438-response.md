## Answers to the decision questions

1. **May the desktop app and `gateway serve` share one store and both serve it?** No. They may share the store; only one may *serve* it at a time. The exclusive lock in `gateway::start` enforces this, and the second one is told which to stop. Other CLI commands are allowed alongside.
2. **How does process B see a failed settlement in process A?** It cannot be in that situation: B cannot serve while A does. When A stops, its settlements are written or its journal entries remain. When A dies, its journal entries remain, and B turns them into interrupted entries when it takes the store. A global degraded flag written to the store (option B) was not chosen because of its timing: the failure it must record is the store refusing writes, which is when such a flag could not be written either.
3. **How much actual usage survives a crash between the provider's reply and settlement?** If the settlement was written, all of it. If it was waiting, which only happens while the store refuses writes, the exact figures were in memory and are lost with the process. The attempt then becomes an interrupted entry with an unknown cost and its held amount at risk. No cost is invented. Writing the figures to a second file was not done: whatever stops the store from writing (a full disk, a read-only volume) would usually stop that file too.
4. **Is a Free/Local 5xx always safe to replay?** No, and the gateway no longer assumes it. A 5xx means the provider may have run the request. A free or local label only says what the user expects it to cost.
5. **Should the user choose availability against replay safety for all billing classes?** Yes. One setting per client now covers every billing class, and its default is to stop.

As the review asked, these were not reopened: the FR-01 allowlist, atomic settlement, the default stop on a 5xx, the measured Anthropic cache parity and the headless Claude Code header result.
