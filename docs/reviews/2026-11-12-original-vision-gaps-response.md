# Counter-review of the original-vision gaps RFC, 2026-11-12

> **Status:** Record · an independent counter-review of [RFC-2026-11-12-ORIGINAL-VISION-GAPS](../archive/RFC-2026-11-12-ORIGINAL-VISION-GAPS.md) (commit `a62efdf`), checked against the code on `main` at `0e2663b` plus that commit · changes nothing by itself: order stays with [ROADMAP](../ROADMAP.md), decisions with [DECISIONS](../DECISIONS.md) · built: [Implementation Status](../IMPLEMENTATION-STATUS.md)

Every row below was checked against the source named in it. Nothing was run live, `cargo test` was not run, and no money was spent. The only outside request was a read of the npm registry (question 3). Where I could not check something, the row says so.

## Verdict

The RFC is mostly accurate about what is missing, and careful about what it does not claim. Its weak point is scope: for almost every item it designs a larger mechanism than the evidence supports, and several of those mechanisms partly exist already. **Two items are right and urgent.** PV-11: the N2 report still has unfilled placeholders, and its raw results are outside the repository. PV-05: the integrations hub is the gap users will hit first. **One item is worth an experiment, in a much smaller form than proposed.** PV-01, a richer handoff between task steps, needs no new tables: the `attempts` rows already hold almost everything it lists. It does not reverse ADR-028, because ADR-028 names "the bounded summary a failed attempt hands to the next step" as what survives. **PV-04 is right but should wait for signing and a single `pygg` binary.** **PV-02, PV-03, PV-07, PV-08 (the adaptive part), PV-09 and PV-10 should stay deferred.** PV-02 is already built in the only form that does not need ADR-028 reversed. PV-03 has almost nothing to decide, because every task attempt is a new agent process with no cache to keep. A shadow decision for PV-08 cannot be scored without paying to run the path that was not taken. I found no safety rule in the RFC that conflicts with an ADR. The places where it needs an owner decision are listed at the end.

- ADR-025 does not mention KV-cache transfer; ADR-017 does. The rule itself is right.

## The RFC's decision questions

1. **Task context without reversing ADR-028? Yes.** *Owned* is what Pygg creates while running a task: the prompt the IDE agent gave it, attempt rows, check output, the diff of each worktree, and the final message each agent printed to Pygg. *Opaque* is everything else: the IDE agent's conversation that called `pygg_run_task`; each agent CLI's internal transcript, tool calls and compaction; provider prompt caches; hidden reasoning and thinking or thought signatures (Gemini's are kept only for the gateway's own replay, `signatures.rs`); CLI session and resume IDs; and the CLIs' sign-ins (ADR-026). None of these can be transferred between Claude Code, Codex, Qwen and GPT. The ADR-028 line runs between "per task, bounded, shown to the user" and "kept across tasks, or presented as memory".
2. **Is the 1,500-character tail a bottleneck? Not shown either way.** In C2 the tail was exactly what let Codex fix what OpenCode missed (AGENTS.md, the cascade live). In N2 it was never tested: after qwen3:8b failed, Haiku solved every case, and Haiku solved them all without help in its own arm (N2 report). **A test that can disprove it:** the 12 `hard-*` cases × 3 repeats, local-first cascade (qwen3:8b, then Haiku), three arms that differ only in the handoff: (a) the task alone, (b) today's tail, (c) PV-01's handoff. Paired by case. Measure the second step's pass rate, its input tokens, its time, and the share of runs where it repeats the first step's failing change. **Drop PV-01** if (c) is not better than (b) on pass rate, and not lower on tokens or time, beyond the paired intervals. Also report (a) against (b): if the tail does not beat nothing, richer context is unlikely to. Estimated cost: 108 paid second steps at about Haiku's $0.013–0.014 per task in N2, so about $1.50, with a strict client limit of $3. Needs the owner's approval out of the remaining $12.67.
3. **npm names.** On 2026-11-12 `npm view` found no published package named `pygg`, `pygg-cli`, `@pygg/cli` or `smarttaskrouter` (all 404). That does not show that npm would accept the name, or that the `@pygg` scope is free. Registering is an owner action. **Same core:** the npm package carries the signed `pygg.exe` in a platform package (`…-win32-x64`), and its `bin` script only runs it. No postinstall download and no second gateway (ADR-005, ADR-021). **Coexistence:** the same data folder and the existing file lock; `pygg serve` refuses a store the app holds, as `gateway serve` does today, and `pygg status` reports the running one. **Minimum matrix:** Windows x64. Nothing else is built (ADR-001).
4. **Reversible setup with consent:** see PV-05. Native logins are kept because only MCP entries and base URLs are written, never an agent's auth files (ADR-026). Targets with live evidence: Claude Code (2.1.317 and 2.1.322), Codex CLI 0.163.0 and OpenCode 1.18.4. Aider, Cursor and VS Code clients stay unverified (ROADMAP E).
5. **Quota facts.** *Obtainable at no cost:* rate-limit headers on API responses where the provider sends them; the gateway already sees Anthropic's and the `x-ratelimit-*` family. I did not check what Gemini or Qwen's token plan send. Also `429`/`Retry-After` resets (already used), and what an agent CLI prints in its own status command (Codex's `login status` is already shown). *Must stay Unknown:* remaining quota of Claude and ChatGPT plans used through their CLIs, organisation-wide limits, monthly token-plan quotas, and anything that would need the user's sign-in. *Pool modes the providers permit:* I did not check any provider's terms for this. Only `pinned` and `failover_only` across keys the user owns are already possible (combos), and ROADMAP E holds the rest.
6. **What could lower cost per kept result:** choosing the first step (N2's local 8B model solved 1 of 36 and only added time; the skip rule already handles a step that stopped answering), and a better handoff, if question 2 says so. Cache affinity at task boundaries cannot help (PV-03). **Data before dynamic scoring:** ADR-006 asks for a minimum sample without a number. My proposal: per category, at least N2's size (12 held-out cases × 3 repeats) per arm, with paired intervals that exclude no difference. Below that, keep the user's strategy.
7. **Smallest meaningful release.** *Must have:* an honest N2 report (PV-11); N6, a paid step approved live; N9, a clean-machine install; the integrations hub for three clients (PV-05); a signed installer (D3, owner's cost). *Experiments:* PV-01's handoff A/B; recording rate-limit headers (PV-06 slice). *Defer or reject:* PV-02 beyond today's tools, PV-03, PV-07, PV-08's adaptive part, PV-09 as a feature, PV-10, and npm before signing.
8. **Already built** (cite before building again): bounded handoff (`tasks.rs:881-899`); attempt evidence (`attempts` columns above); policy snapshot and strategies (`tasks.rs:30`, `1428`); quality signals (`0015`, `tasks.rs:843`); skip rule (`tasks.rs:902-931`, test `a_step_that_twice_timed_out_without_answering_is_skipped_unless_it_is_the_last`); session pins (P0-4); one store per gateway (`tests/two_gateways.rs`); client-supplied context and a read-back for IDE agents (`mcp.rs:60`, `:73`); passive client check (`Overview.tsx:109`); headless programs in the installer. **ADR conflicts:** PV-02's envelope (ADR-028). None elsewhere, as long as PV-01 stays per task.

## What only the owner can decide

1. **PV-01 under ADR-028.** My reading is that a bounded, per-task handoff is what ADR-028 already keeps. A short dated Update note under ADR-028 saying so would settle it; that is the owner's call, not a reversal.
2. **Money for the handoff A/B:** about $1.50 estimated, capped at $3, out of the $12.67 left of the $20 benchmark budget (ADR-028). Also any later runs on larger repositories or a second agent.
3. **The npm name and scope**, and whether an npm package for Windows x64 only is worth publishing before other platforms are built.
4. **The code-signing certificate (D3)**, a cost, which I would make a prerequisite of the npm launcher.
5. **Whether to reopen ADR-028 for cross-client chat context (PV-02).** My recommendation is no.
6. **Account pools (PV-07):** only if the owner has API keys with independent quotas and has read the provider's terms for them.
