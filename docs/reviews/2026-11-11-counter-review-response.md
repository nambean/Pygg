# Response to the architect counter-review, 2026-11-11

> **Later changes:** the [follow-up review response](2026-11-11-remaining-gateway-risks-response.md) changes three answers below. A server error no longer falls back by default (CR-05). Client tokens can be restricted to named connections (CR-01: privacy across fallback). No paid request is admitted while a ledger entry waits to be written (CR-06). Cache parity has been measured (question 5).

Responds item by item to the [counter-review](2026-11-11-architect-counter-review.md) of the [architect decisions](2026-11-11-architect-decisions.md) and the P0-1 to P0-4 code. Every row was checked against the source before it was decided, and every accepted change is in the commit that adds this note, with the tests named below. What runs and how it was verified is in [Implementation Status](../IMPLEMENTATION-STATUS.md).

**Result:** CR-03, CR-04, CR-06, CR-07, CR-08 and CR-09 are accepted. CR-01, CR-02 and CR-05 are accepted in part. Nothing is rejected outright. The parts not taken are listed with a counterexample or a reason. `cargo test` now gives 84 passed and 1 ignored (it was 67); the 17 new tests are listed per item.

The review asked for one thing it did not find: a bug. Checking CR-01 showed that the quota-group rule held only *within* the request that hit the refusal. A later request could go straight to a sibling key of the same group, which is exactly the account cycling the rule exists to stop. That is fixed (CR-01, first row).

### What was not taken, and why

- **CR-01, fail closed on every 401/402/403.** A combo is the user's explicit, ordered fallback policy: every target in it was put there by the user. Refusing all of them after one 402 would turn "Anthropic is out of credit, use my OpenRouter backup" into a failed request. No terms are broken, because the backup is another provider or another quota group. What stays closed: the rest of the quota group, for as long as the refusal lasts. What the review rightly adds, data-use and privacy compatibility across a fallback, needs data-use terms per preset (GW-10). That is a hard filter of P0-5, not a property of an HTTP status.
- **CR-01, account-level versus model-level scope from the status alone.** It cannot be known, and the code no longer pretends to. Where the provider does not say, the cooldown is set on the narrowest scope that a refusal could have (the model on that connection), and the whole quota group is kept off that model. Another model on the same key may still be tried; that is ordinary use of one key, and a provider with an account-wide limit refuses it at no cost.
- **CR-05, stop on 425.** RFC 8470 §5.2 defines 425 as the server declining to process a request sent in TLS early data, so it did not run it. The gateway does not send early data, so it should not see a 425 at all. If one comes, falling back is safe by definition.
- **CR-02, provider-verified organization fields.** None of the presets offers a documented call that returns the organization and quota scope of a key, so the fields would be the user's guess under another name. They wait until a provider adapter can fill them from a source.

## Answers to the review's questions

1. **402/403/429 scope.** No preset provider reports the scope of a limit in a consistent, documented field. Known codes are used: OpenAI's `insufficient_quota` and `billing_hard_limit_reached` are account-wide; Gemini's `RESOURCE_EXHAUSTED` carries `RetryInfo`, which is read. When the scope is unknown, the model on that connection cools down, and the rest of its quota group stays off that model until the reset. Other targets of the combo, chosen by the user, may answer.
2. **Can a user-confirmed independent group still break a shared upstream limit?** Yes, if the confirmation is wrong. The gateway cannot detect that, so it does not claim to. The confirmation sheet says so, the date is stored, and the provider's own refusals still cool each connection down. The default remains "shared".
3. **Which bounds make the cap enforceable for every provider?** None that are available today. That would need a verified tokenizer per model, a verified maximum output, verified prices including cache writes, and usage reported on every path. The UI says the limit is checked against an estimate and that the bill can be higher. Spend at risk is counted, and an overrun is shown and stops the next request. A strict mode that refuses when any bound is unknown is planned with the P0-5 catalog.
4. **SQLite commits the usage event but fails to delete the reservation, or fails before writing it.** Neither can happen apart any more: both are one transaction. If the transaction fails, both are rolled back, the journal entry still holds its spend, and it is retried. If it is never settled, it becomes an interrupted entry, either when the attempt is dropped or at the next start after an hour. If the journal cannot be written before sending, nothing is sent.
5. **Native Anthropic semantics and cache parity.** The semantics preserved are listed in the matrix below. **Measured** with the owner's key (`scripts/anthropic-parity.ps1`, claude-haiku-4-5): two turns with `cache_control`, direct and through the gateway, streamed and not, gave identical counts. Turn 1 wrote 9011 cached tokens and turn 2 read 9011, in both arms. Thinking with a tool call and citations on a document also came back with the same blocks. Details in [Implementation Status](../IMPLEMENTATION-STATUS.md#provider-parity-anthropic-direct-versus-through-the-gateway-2026-11-11). Not covered: the 1-hour TTL, a multi-turn tool round trip, other models.
6. **Does Claude Code send the session header consistently?** Yes, in a headless session (run with the owner's go-ahead, details in [Implementation Status](../IMPLEMENTATION-STATUS.md#live-verification-claude-code-through-the-gateway-2026-11-11)). Claude Code 2.1.317 ran four invocations of one session through the gateway to Gemini: file write and read, a sub-agent, `/compact`, an edit. The gateway's request log shows the header on 12 of 12 requests, the sub-agent's and the compaction's included; there was no `count_tokens` call to check. Still open: an interactive terminal session, which may send background requests that `-p` does not.
7. **HTTP-date Retry-After and resets of 24 h or more.** Tested (CR-04 row): an HTTP date a day ahead gives a 24 h cooldown, skew is measured against the response's `Date`, and a 30 h reset is kept rather than cut to 6 h.
8. **Is P0-5 a hard filter or a cheapest-first alias?** It is designed as a hard filter. A model enters `auto` only if its catalog entry has a sourced price, capability flags, a context size and a maximum output, each with a source and a date. Budget, privacy and capability filters come first, then cost ordering; a model with any of those fields unknown is not eligible. It is not built yet.

## Native passthrough: fields and headers (CR-08)

"Kept" means the value reaches the provider unchanged. The request body is parsed and written again with the same keys in the same order; only `model` is replaced with the target's model id.

| Item | Anthropic → Anthropic connection | Anthropic → OpenAI-compatible (translated) |
| --- | --- | --- |
| `system`, `messages`, text, images | Kept | Translated |
| `tools`, `tool_choice`, tool calls and results | Kept | Translated (server tools dropped) |
| `cache_control` | Kept | Kept for OpenRouter; otherwise dropped and listed in `x-smarttaskrouter-dropped` |
| `thinking`, thinking blocks | Kept | Dropped and listed |
| Citations, documents, other block types | Kept | Dropped and listed by type |
| Server tools (no `input_schema`) | Kept | Dropped and listed as `server_tools` |
| `stop_sequences`, `temperature`, `top_p` | Kept | Translated |
| `top_k`, `metadata`, `service_tier`, `container`, `mcp_servers` | Kept | Dropped and listed |
| `anthropic-version` header | Forwarded (default `2023-06-01`) | Not applicable |
| `anthropic-beta` header | Forwarded | Not applicable |
| Other client headers (`user-agent`, `x-app`, `x-stainless-*`) | Not forwarded | Not forwarded |
| Response body | Unchanged | Translated back |
| Response `anthropic-ratelimit-*`, `request-id` | Passed back | Not applicable (OpenAI `x-ratelimit-*` are not passed back on a translated answer) |
| Usage: input, output, cache read, cache write | Read into the ledger | Input, output and cache read; no cache write |
| Errors | The provider's body and status, unchanged | Translated into the Anthropic error format |
| `count_tokens` | Forwarded to the connection | Estimated, labeled `x-smarttaskrouter-estimate` |

For OpenAI → OpenAI-compatible, the request is kept the same way and `stream_options.include_usage` is added to streamed requests so their cost can be read. The provider's `x-ratelimit-*` and `x-request-id` come back.

## Fallback matrix (CR-01, CR-05)

| Failure | This request | Cooldown | Cost in the ledger |
| --- | --- | --- | --- |
| Could not connect | Next target | Connection, 15 s | $0, not sent |
| Read timeout, reset after sending | **Stop** | None | Unknown, held amount at risk |
| 401 | Other quota groups only | Connection, until the key is replaced | $0, rejected |
| 402; 429 with `insufficient_quota` | Other quota groups only | Connection, `Retry-After` or 10 min (1 h for out of credit) | $0, rejected |
| 403 | Other quota groups only | Model, `Retry-After` or 10 min | $0, rejected |
| 429 | Other quota groups only | Model, `Retry-After` / date / `retry-after-ms` / Gemini `RetryInfo`, or 30 s | $0, rejected |
| 404 | Next target | Model, 5 min | $0, rejected |
| 408, 504, 524 | **Stop** | None | Unknown, held amount at risk |
| 409, 400, 413, 422 and other 4xx | **Stop** | None | $0, rejected |
| 425 | Next target | None | $0, rejected |
| Other 5xx | **Stop**, unless the client allows paid retries or the connection is free or local ([follow-up FR-02](2026-11-11-remaining-gateway-risks-response.md)) | Model, `Retry-After` or 15 s | Unknown, held amount at risk |

"Other quota groups only" also holds for later requests: while a refusal is active on a connection, other connections of its quota group are not used for the covered model (for any model, when the refusal covers the whole connection).
