## Verification level of P0

The levels are cumulative. **Fake-tested** means end-to-end tests against the fake provider in `gateway/tests.rs`. **Live-tested** means a real provider answered through the gateway. **Provider-parity-tested** means the same request went direct and through the gateway, and cost and fields were compared. **Release-ready** means all of that, plus the ROADMAP's benchmark and security gates.

| **Same-format passthrough** (ROADMAP P0-1) | Every connection has a wire format (`openai` or `anthropic`). Requests in the same format go through as a **native-format semantic passthrough**: the JSON is written again with its keys in the client's order and only `model` replaced; for Anthropic that keeps `cache_control`, thinking, citations and every other field, and forwards `anthropic-version` and `anthropic-beta`. The answer body comes back unchanged with the provider's rate-limit and request-id headers, and Anthropic usage (cache read and write) is read on the way. Anthropic → OpenAI translation keeps cache markers for OpenRouter and names everything it drops in `x-smarttaskrouter-dropped`. **What is left** (`quota.rs`, ROADMAP E): the rate-limit headers a provider last sent are read as windows (limit, remaining, reset; Anthropic, OpenAI/Groq and OpenRouter forms, Retry-After), shown in Connections, and `auto` skips a model whose stated limit is used up until its reset; OpenRouter's `/key` and DeepSeek's `/user/balance` are read at start-up, after a model refresh and with Check Now, and OpenRouter's free models are skipped once the day's free requests are used up. | **Responses API** (ADR-033, `responses.rs`, 2026-11-12) | `POST /v1/responses`, for Codex CLI (which refuses Chat Completions) and other Responses clients, on the same routing, `auto`, combos, limits, holds, sessions and ledger. To an OpenAI-format connection: translated to Chat Completions and back; to an Anthropic one: through the Chat Completions → Messages translator and back; to a provider whose preset serves `/responses` (OpenAI): native passthrough, usage read from `response.completed`. Streamed answers are Responses events (`response.created`, `output_item.added`/`.done`, `output_text.delta`, `function_call_arguments.delta`, `custom_tool_call_input.delta`, reasoning summary or text deltas, `response.completed`, `.incomplete` or `.failed`). Custom (free-form) tools cross as a function with one string `input` and come back as `custom_tool_call`; `namespace` tools as `<namespace>__<name>`; provider reasoning comes back as a reasoning item and goes back as `reasoning_content` where taken. | **Error-scoped fallback and cooldown** (P0-2, `policy.rs`) | Fallback happens only before any byte reaches the client. 401 blocks the connection until its key is replaced. 402, 403 and 429 cool the model or connection down and never move to *another connection in the same quota group*, in that request **or later ones while the cooldown lasts**; the same connection's other models may still answer. OpenAI's `insufficient_quota` cools the whole connection. An account out of credit (`payment_required`, HTTP 402) does not hold the models that are free without credit: those listed at $0 on a connection kept for its free models (OpenRouter's `:free` ones, ADR-032), on that connection or a sibling key; a 402 answered by such a model is kept on that model, and an answer from one does not clear the connection's 402 (2026-11-12). The reset is read from `Retry-After` (seconds or HTTP date, measured against the response's `Date`), `retry-after-ms` or Gemini's `RetryInfo`, and kept as stated (up to 7 days). A read timeout after sending, and HTTP 408, 504 and 524, stop with an Unknown cost and do not pay a second provider. A refused connection may fall back. Other 5xx stop too, on every billing type, unless the client allows retries after a server error (1 to 5). **One gateway serves a store at a time**: `gateway::start` takes an exclusive OS file lock on `<store>.gateway-lock`, a second app or `gateway serve` on the same store is refused before it sends anything, and the lock goes with the process however it ends. The ownership is held by the server, by every attempt in flight and by every waiting settlement, and the lock is released only when the last of them is settled: a stopped gateway still finishing a long answer or stream keeps the store, refuses new work (503) and settles with the real cost; starting again in the same process joins that ownership. Each ownership has a generation written on its journal entries; a gateway taking the store turns every entry of another generation into an interrupted entry, and if it cannot, it does not start. `gateway serve` waits for requests in flight on Ctrl+C (a second Ctrl+C stops at once). A client token can be restricted to named connections: a restricted client never reaches another one, by combo, fallback, session pin, direct request or `count_tokens`. Cooldowns are stored per connection and model, and are shown and clearable in Connections. The quota group defaults to the provider kind; a connection can be confirmed as having an independent quota. Full matrix: [counter-review response](reviews/2026-11-11-counter-review-response.md#fallback-matrix-cr-01-cr-05). | Tests: 429 → 503 → OK with later requests skipping the cooled-down models; sibling key not tried, now or in later requests; account out of credit; an OpenRouter 402 leaves its `:free` models in use; 24 h reset kept; 408 and 504 not retried; 401 blocks until cleared; timeout not retried; every Retry-After form; live: missing model cooled down and skipped on the next request |
| **Budgets, concurrency, complete ledger** (P0-3) | **Every attempt is journaled before it is sent**; if the journal cannot be written, nothing is sent (HTTP 503). The ledger entry and the journal removal are one transaction. An attempt never settled (a panic, a crash) becomes an *interrupted* entry with an unknown cost. A client with a limit holds an **estimate** of each attempt's cost atomically (`BEGIN IMMEDIATE`): the prompt with non-ASCII characters counted as a token each, at the higher of the input and cache-write prices, plus `max_tokens` (or 4096) at the output price. It is settled from real usage. The limit is an estimated admission limit, not a hard cap: the bill can exceed it, and the UI says so. Spend **at risk** (an unknown cost after the request reached the provider) counts against the limit at its held amount. Requests in flight are capped per client (8 by default). A target with an unknown price is blocked for a client with a limit unless the client allows it. Handlers run detached, so a client that disconnects early still leaves a ledger entry. A settlement that cannot be written is kept with its exact figures and retried before every request; **while one waits, no paid target is sent**. Settlement is exactly once. It shows in `/health` and on Overview. | Tests: two concurrent requests against a limit that fits one (200 and 429); spend above the estimate recorded and the next request refused; server error counted at risk; estimate for CJK, Vietnamese and cache writes; no journal entry left after five attempts; nothing sent with a read-only store; interrupted entries; unknown price blocked, then allowed; in-flight cap; disconnect before the answer is still recorded |
| **Explicit session affinity** (P0-4) | `x-smarttaskrouter-session` (at most 128 visible ASCII characters, anything else ignored) pins a session to the target that last answered it (2 h sliding) while that target is still on the route; others remain as fallbacks. Pins are scoped to the client token, and expired pins are deleted. Sessions are never guessed from prompt content. The Claude Code snippet sets a new session id per terminal through `ANTHROPIC_CUSTOM_HEADERS`. | Tests: a session stays on the backup after one fallback while requests without a session return to the first model; same id from another client not shared; long and non-ASCII ids ignored; expired pins deleted; live: `x-smarttaskrouter-session: pinned`, 1 call |
| **Auto routing** (P0-5, `auto.rs`) | `auto` and `auto/cheap` are model names. The route is built when the request arrives, from the enabled models of enabled connections. **Hard filters come first**, each with a readable reason. The model must be on the client's connection list, reachable from the request's API format, not cooling down and not held by its quota group. It must be *known* to take tools or images if the request has them, and, for a native Anthropic target, the thinking type and effort level an Anthropic request asks for (schema v12, from Anthropic's model list or the user; checked against the live list: `claude-haiku-4-5` takes neither adaptive thinking nor effort). A client that requires providers not to train on its data reaches only connections recorded so (schema v13, Connections → Data use). Its context must fit the estimated prompt plus the output limit. Its maximum output must cover a limit the request sets. Its cost must be statable (a price, or free, local or subscription billing; a subscription uses a plan's quota and ranks after free, before paid). For `auto` its tier must be set and at or above the client's minimum (T2 by default): the user's tier, or a starting tier from Pygg's table (`gateway/tiers.rs`, `curated:v1`, by each vendor's naming of its model line) where nobody set one. Unknown counts as missing. **Ranking uses rules only, with no classifier and no invented quality scores.** `auto` takes the lowest eligible tier, then local, free, subscription and paid, then the lower estimated cost: "the lowest eligible tier under your policy" (ADR-006). `auto/cheap` takes the lowest estimated cost of the request. The first five form the route, under the usual fallback, quota, budget and retry rules. An explicit session stays on the model that first answered it. Each response says which model answered, its rank and why in `x-smarttaskrouter-auto`, and the ledger keeps the reason. With nothing eligible the request is refused (422) with the reasons grouped by connection and reason, the largest group first, each with an example model and how many more share it (2026-11-12: an owner's 584 models had been refused with the first 12 reasons, all from one connection). **Model facts:** tier, context, maximum output, tools and images, each with a source. They are read from the provider's model list where it reports them (OpenRouter: all but the tier, plus a list price; Groq and others: a context window) or set by the user. What the user sets is never overwritten by a refresh. **The reference catalog** (`gateway/reference.rs`, ADR-031) fills what the provider's list leaves out from models.dev (context, output, tools, images, list price; source named), and models the naming table does not know get a tier from their list price band (`price-band:v1`); it runs at start-up and after a refresh, at most one download a day, cached next to the store. **A connection kept for its free models** (OpenRouter, Z.AI; ADR-032, schema v20) has only its $0 models on while it is set as free: paid and unpriced models start off, say why, and come back on if the connection is set as paid; the ledger bills them by the same rule, and Z.AI's free Flash models, missing from its list, are added from the catalog. Claude models on an Anthropic connection are marked as taking tools from Anthropic's documentation (`curated:v1`, named in the facts' source), since Anthropic's model list does not say so; a user's own setting stands. `auto` is reserved as a connection and combo name. | Unit tests for filters and ranking; end-to-end: lowest tier and free first, tools need known support, `auto/cheap`, refusal with reasons, unknown alias refused, session kept when a better model appears, client minimum and allowlist; catalog parsing of OpenRouter and context-window lists; user facts and prices not overwritten. Live: Gemini, Anthropic, Qwen's token plan and Claude Code (below) |
| Streaming | Server-sent events pass through unchanged. Usage is read from the final chunk (`stream_options.include_usage` is requested). If the client disconnects or the stream breaks, the outcome is recorded with an unknown cost. | Tests; live |
