# Security

> **Status:** Current · what Pygg protects and how, what the user is trusted with, and how to report a problem · reviewed 2026-11-14

Pygg holds API keys, sends source code and prompts to providers, runs agent CLIs and the checks a user approved, and spends money. Everything runs on the user's machine (ADR-002).

## Reporting a problem

Report a vulnerability privately, not in a public issue: with [Report a vulnerability](https://github.com/nambean/Pygg/security/advisories/new) on the repository's Security tab. Include the version or commit, what you did and what happened. Do not include real keys or tokens.

## What Pygg protects, and how

| Asset | Protection | Code |
| --- | --- | --- |
| Provider keys | Kept in the OS credential store (Windows Credential Manager; the macOS Keychain or the desktop keyring for the command line); the store holds only a reference, one per key when a connection holds keys of several accounts. A key goes into the core once and never comes back out to the interface. The command line reads keys from an environment variable, never from its arguments. A connection's endpoint must be `https://`, or `http://` only to this computer or the local network (loopback, private and link-local addresses, names without a dot, `.local`, `.lan`, `.internal`), so a key never crosses the internet unencrypted | `vault.rs`, `commands.rs`, `cli/gateway.rs` |
| Pygg API keys (client tokens) | The store keeps only a fingerprint of each key: its SHA-256 hash, and its first 12 characters so the user can tell keys apart. A key created in Endpoint → API Keys, and the Claude Code launcher's key, also keep a copy in the OS credential store, which **Show** reads back. A key made by `pygg gateway create-client` or by a tool's one-click set-up (whose token is written into that tool's own configuration file) has no copy and is shown once. Revoking a key deletes its copy; deleting a revoked key takes it off the list, and its past requests keep its name. Each key can be limited (money, requests in flight, the connections it may use, providers that must not train on its data) and revoked. **Defaults for new keys** (Policies) apply to every way a key is created; a limit given at creation wins, and existing keys keep theirs. Not verified yet: reading a copy back from the real Credential Manager (no automated test) | `gateway/store.rs`, `commands.rs`, `vault.rs` |
| The gateway | Listens on `127.0.0.1` only. Refuses a `Host` that is not a loopback name (DNS rebinding). Every API route needs a Pygg API key, except `/health`, which says only that Pygg is running | `gateway/mod.rs` |
| Spending | Atomic admission against a key's limit (an estimate, or the most a request could cost when the limit is strict). Every attempt is journaled before it is sent and settled exactly once. No paid request goes out while the ledger cannot be written. An unknown cost is never shown as $0. A paid task step needs the user's approval with a cap, and there is no API to approve one | `gateway/mod.rs`, `tasks.rs` |
| Where data goes | Per connection, the data-use terms the user recorded. A key can require providers that do not train on its data, enforced on every route. A sensitive workspace asks before every agent step | `gateway/store.rs`, `tasks.rs` |
| The user's code | Agents work in a Git worktree of a recorded commit, never in the user's checkout. A result is kept as a new branch or a patch only when the user says so | `isolation.rs` |
| Output and logs | Secrets are removed from agent and check output before it is stored or shown. Notifications name no task or file | `redact.rs`, `shell.rs` |
| The diagnostics bundle | Saved only when the user asks (Settings → Diagnostics, or `pygg diagnostics --out PATH`) and never sent anywhere by Pygg. Built from an allowlist: app, schema and Windows versions; gateway state and port; each connection's kind, endpoint without user name, query or fragment, enabled state, billing, terms, health and whether a key is set; key names and limits; row counts per table; the latest 200 ledger rows without the provider's error text or session key; task and step states. It never reads provider keys, client tokens or their hashes and prefixes, connection labels, prompts, task titles or reasons, agent or check output, diffs or file contents. Every text value is cut to 200 characters and redacted, and each file is redacted again. A test builds a bundle from a store holding a fake key, a token and a prompt, and finds none of them | `diagnostics.rs`, `commands.rs`, `cli/mod.rs` |
| Usage history | Kept until the user picks 30, 90 or 365 days (Settings → Usage History). Then older ledger rows and route decisions are deleted from the local store at start-up and once a day, after a confirmation that says how many go. Rows a task's cost is counted from, and this month's rows, which key limits count, are kept, so a deletion never lowers a task's cost or frees room under a monthly limit. Deleted rows stay on disk until SQLite reuses the space | `retention.rs`, `commands.rs` |
| Outbound requests of its own | Apart from what clients and agents send through it, Pygg contacts only the providers the user connected (a web session's window loads its site, and wherever the user goes while signing in there) and, at most once a day, [models.dev](https://models.dev) for its public model catalog (ADR-031): a plain GET that carries no key, token or prompt | `gateway/reference.rs` |
| Signing in with a provider | Only a provider's own OAuth that issues an API key (OpenRouter's PKCE). The browser goes to the provider, the callback listens on `localhost` only and checks the state, and the key goes straight to the credential store. No cookie or website session is read or kept (ADR-034, ADR-026) | `gateway/oauth.rs` |
| Sign-ins of agents | Agent CLIs run with their own sign-in. Pygg never reads, stores or forwards it, and never bridges cookies or other products' OAuth (ADR-026) | `agents.rs` |
| The Claude Code launcher | Claude Code's own settings and sign-in are never changed. `pygg run claude` starts it with the gateway's address, the launcher's Pygg API key, the model (`auto` unless `--model` is given) and a fresh session header, in **that one process's environment only**. The key ("Claude Code (launcher)") is kept in the Windows Credential Manager, never in a file, and read from there at each launch; `pygg run` opens the store read-only. Before the launch it removes `ANTHROPIC_API_KEY`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` and the host session's variables (`process::HOST_SESSION_VARS`), so neither another key nor a parent session reaches the gateway. Remove (CLI Tools, or `pygg setup claude --remove`) revokes the key and deletes it from the Credential Manager | `launcher.rs`, `cli/run.rs`, `process.rs` |
| Web sessions (ADR-035) | A site (Muse, ChatGPT, Perplexity, DeepSeek, Grok) is used through a Pygg window the user signs in to.<br>**Profile.** Each connection has its own WebView2 profile folder, so no site sees another connection's cookies, storage or sign-in. WebView2 keeps the sign-in there, encrypted for the Windows user.<br>**No cookie import, no password.** Pygg never asks for or stores a password and never imports or reads cookies. Its page scripts only fill the prompt box, press Send, read the reply and click the site's own **deny** on an agent's request to act (test `no_script_reads_cookies_storage_or_the_network`).<br>**Where the window may go.** While the user has the window open to sign in, it may go to any https address, like a browser. Otherwise it keeps to the recipe's hosts ([PROVIDERS.md](PROVIDERS.md)).<br>**Where Pygg types.** Pygg fills the prompt box and presses Send only when the page is the site's own host over https; sign-in hosts such as Google do not count. Anywhere else it sends nothing and marks the connection Needs you (test `pygg_types_only_on_the_sites_own_page`).<br>**What is recorded.** A refused address, every popup (all are denied) and a non-https address are recorded on the connection by host or scheme only.<br>**A person's pace.** The guard holds each account to one request at a time, a rest after each reply, and limits per 10 minutes, per hour and per day, weighted by prompt size; it refuses long prompts and backs off on signs of trouble, and turns the connection off when the site says the account is suspended ([PROVIDERS.md](PROVIDERS.md) gives the numbers). At a limit the gateway answers 429 with Retry-After, and nothing reaches the site.<br>**No disguise.** Pygg never changes a window's browser fingerprint (user agent, client hints, canvas, fonts and the like) and never randomises its timing. It never solves, skips or hides from a CAPTCHA, a sign-in page or a bot check: such a check stops the connection and tells the user to deal with it in the window.<br>**Debugging.** DevTools (remote-debugging port 9462) and a log of each navigation decision exist only in debug builds, and only with `PYGG_WEB_DEVTOOLS` set. The log prints each address in full to the console, nothing from the page. Release builds have neither.<br>**Kept apart from Pygg.** The window has no Tauri capability, so the site cannot call Pygg's commands. The gateway reaches it through a loopback endpoint on a random port, behind a token that exists only in memory. Errors and the stored sign-in state are Pygg's own wording, never the page's text. The ledger, diagnostics and exports never name the profile folder.<br>**Lifecycle.** Each connection needs the user's acknowledgement of the account risk and starts off. It refuses tools and is never chosen by `auto`. Removing the connection closes its window and deletes its folder; a folder still held is deleted at the next start, before any window opens.<br>Verified by the tests in `websession/tests.rs` with a scripted page, and live against the five sites | `websession/mod.rs`, `websession/guard.rs`, `websession/window.rs`, `gateway/store.rs`, `commands.rs` |

## What the user is trusted with

- **Checks run code.** An approved check runs the code an agent wrote, on this computer, with the user's rights. Detected checks are only suggestions until approved.
- **Agents can run commands** where their own tools allow it. Pygg gives them file tools by default, and a shell only when the user allows it (Claude Code's Bash, Gemini's yolo mode). Codex keeps its own sandbox.
- **The data folder** holds prompts, ledger entries and agent output, and each web session's profile folder with its sign-in. It is the user's to protect, like any other local file.
- **A web session's window is a browser while the user signs in.** Whatever the user opens there in that time is kept in that connection's profile folder, as a browser would keep it.
- **A web session acts as the user on the site.** The site's terms may forbid automated use, and the account can be limited or banned; the user accepts this per connection (ADR-035). For an agent like Muse, what a client sends through Pygg is sent from the user's account, though Pygg denies every action the agent asks to take.
- **Keys of several accounts on one connection.** Pygg cannot check that the keys of a key ring belong to separate accounts; the user confirms it (ADR-038).
- **`PYGG_CAPTURE_DIR`**, a debugging aid, writes translated streams (whole model answers) to that folder. Leave it unset except when diagnosing.

## Not covered yet

- Signed builds and a signed updater: installers and the npm packages are unsigned ([ROADMAP.md](ROADMAP.md)).
- A security review of the agent CLIs themselves, which Pygg runs but does not control.
- Multi-user or remote use: Pygg assumes one user on one machine.
