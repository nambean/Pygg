# Security

> **Status:** Current · what Pygg protects, how, and how to report a problem · reviewed 2026-11-13 · order: [ROADMAP](ROADMAP.md) · built: [Implementation Status](IMPLEMENTATION-STATUS.md)

Pygg holds API keys, sends source code and prompts to providers, runs agent CLIs and the checks a user approved, and spends money. Everything runs on the user's machine (ADR-002).

## Reporting

Report a vulnerability privately: through the repository's Security tab (private vulnerability reporting) where it is enabled, or to the maintainer directly; not in a public issue. Include the version or commit, what you did and what happened. Do not include real keys or tokens.

## What is protected, and how

| Asset | Protection | Where |
| --- | --- | --- |
| Provider keys | Kept in the OS credential store (Windows Credential Manager, macOS Keychain); the store holds only a reference. A key goes into the core once and never comes back out to the interface. Keys are read from an environment variable by the headless CLIs, never from a command line | `vault.rs`, `commands.rs`, `bin/gateway.rs` |
| Pygg API keys (client tokens) | The store keeps only a fingerprint of each key: its SHA-256 hash, and its first 12 characters so the user can tell keys apart. Since schema v23, a key created in Endpoint → API Keys and the Claude Code launcher's key also keep a copy in the OS credential store (Windows Credential Manager) under a `client-…` reference (`vault::new_client_reference`, `gateway_clients.token_ref`). **Show** reads that copy back. Revoking a key deletes its copy; deleting a revoked key takes it off the list, and its past requests keep its name. A key made before v23, by `gateway create-client`, or by a tool's one-click set-up (whose token is written into that tool's own configuration file) has no copy and is shown once. Each key can be limited (money, requests in flight, connections it may use, providers that must not train on its data) and revoked. **Defaults for new keys** (Policies) are applied inside `store::create_client`, so every creation path gets them: Endpoint, `gateway create-client`, a tool's set-up and the launcher. A limit given at creation wins, and existing keys keep theirs. Verified by unit tests (`a_revoked_key_can_be_deleted_and_is_then_not_listed`, `new_keys_get_the_defaults_and_old_keys_keep_theirs`; passed 2026-11-13). Reading a copy back from the real Credential Manager has no automated test | `gateway/store.rs`, `commands.rs` (`client_create`, `client_token`, `client_revoke`, `client_delete`), `vault.rs` |
| The gateway | Listens on `127.0.0.1` only; refuses a `Host` that is not a loopback name (DNS rebinding); every request needs a client token | `gateway/mod.rs` |
| Spending | Atomic admission against a client's limit (an estimate, or the most a request could cost when the limit is strict); every attempt journaled before it is sent and settled exactly once; no paid request while the ledger cannot be written; unknown cost never shown as $0; a paid task step needs the user's approval with a cap, and there is no API to approve | `gateway/mod.rs`, `tasks.rs` |
| Where data goes | Per connection, data-use terms the user recorded; a client can require providers that do not train on its data, enforced on every route; a sensitive workspace asks before every agent step | `gateway/store.rs`, `tasks.rs` |
| The user's code | Agents work in a Git worktree of a recorded commit, never in the user's checkout; results are kept as a new branch or a patch only when the user says so | `isolation.rs` |
| Output and logs | Secrets are removed from agent and check output before it is stored or shown; notifications name no task or file | `redact.rs`, `shell.rs` |
| The diagnostics bundle | Saved only when the user asks (Settings → Diagnostics, or `pygg-cli diagnostics --out PATH`) and never sent anywhere by Pygg. Built from an allowlist of columns: app, schema and Windows versions; gateway state and port; each connection's kind, endpoint without user name, query or fragment, enabled state, billing, terms, health and whether a key is set; client names and limits; row counts per table; the latest 200 ledger rows without the provider's error text or session key; task and step states. It never reads keys (they stay in the OS credential store), client tokens or their hashes and prefixes, connection labels, prompts, task titles or reasons, agent or check output, diffs or file contents. Every text value is cut to 200 characters and redacted, and each file is redacted again; a test builds a bundle from a store holding a fake key, a token and a prompt and finds none of them | `diagnostics.rs`, `commands.rs`, `cli/mod.rs` |
| Usage history | Kept forever unless the user picks 30, 90 or 365 days (Settings → Usage History); then older ledger rows and route decisions are deleted from the local store at start-up and once a day, after a confirmation that says how many go. Rows a task's cost is counted from and this month's rows, which client limits count, are kept, so a deletion never lowers a task's cost or frees room under a monthly limit. Deleted rows are not overwritten on disk until SQLite reuses the space | `retention.rs`, `commands.rs` |
| Outbound requests of its own | Apart from what clients and agents send through it, Pygg contacts only the providers the user connected (a web session's window loads its site, and wherever the user goes while signing in there) and, at most once a day, [models.dev](https://models.dev) for its public model catalog (ADR-031): a plain GET that carries no key, token or prompt | `gateway/reference.rs` |
| Signing in with a provider | Only a provider's own OAuth that issues an API key (OpenRouter's PKCE): the browser goes to the provider, the callback listens on `localhost` only, checks the state, and the key goes straight to the credential store; no cookie or website session is read or kept (ADR-034, ADR-026) | `gateway/oauth.rs` |
| Sign-ins of agents | Agent CLIs run with their own sign-in; Pygg never reads, stores or forwards it, and never bridges cookies or other products' OAuth (ADR-026) | `agents.rs` |
| The Claude Code launcher | Claude Code's own settings and sign-in are never changed. `pygg run claude` starts it with the gateway's address, the launcher's Pygg API key, the model (`auto` unless `--model` is given) and a fresh session header, in **that one process's environment only**. The key ("Claude Code (launcher)") is kept in the Windows Credential Manager, never in a file, and is read from there at each launch; `pygg run` opens the store read-only. Before the launch it removes `ANTHROPIC_API_KEY`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` and the host session's variables (`process::HOST_SESSION_VARS`: `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_OAUTH_SCOPES` and the like), so neither another key nor a parent session reaches the gateway. Remove (CLI Tools, or `pygg setup claude-launcher --remove`) revokes the key and deletes it from the Credential Manager. Verified by unit tests (`launcher::tests`, passed 2026-11-13) and live on 2026-11-12 on a scratch store (commit d12443f): Claude Code 2.1.322 reached the gateway with the launcher's key (refused with 422, as no provider was connected), a stopped gateway was caught before the launch, and Remove left no credential behind | `launcher.rs`, `cli/run.rs`, `process.rs` |
| Web sessions (ADR-035) | A site (Muse, ChatGPT, Perplexity, DeepSeek, Grok) is used through a Pygg window the user signs in to themselves.<br>**Profile.** Each connection has its own WebView2 profile folder (`websessions/p-<random>`, named by `store::add_web_provider`), so no site sees another connection's cookies, storage or sign-in. WebView2 keeps the sign-in there, encrypted for the Windows user.<br>**No cookie import, no password.** Pygg never asks for or stores a password and never imports or reads cookies. Its page scripts only fill the prompt box, press Send, read the reply and click the site's own **deny** on an agent's request to act (test `no_script_reads_cookies_storage_or_the_network`).<br>**Where the window may go.** While the user has the window open to sign in (Open Sign-In Window, until they close it or Check Sign-In finds the session signed in, which hides it), it may go to any https address, like a browser: sign-in passes through hosts no list foresees. Otherwise it keeps to the recipe's hosts (`host_allowed`; recipes with Google sign-in also allow `accounts.google.<country>`).<br>**Where Pygg types.** Pygg fills the prompt box and presses Send only when the page is the site's own host over https (`site_host`, checked inside `fill_script` and `send_script`; sign-in hosts such as Google do not count). Anywhere else it sends nothing and marks the connection Needs you (test `pygg_types_only_on_the_sites_own_page`).<br>**What is recorded.** A refused address, every popup (all are denied) and a non-https address are recorded on the connection by host or by scheme only (`store::set_web_blocked`, from `websession/window.rs`), so a stalled sign-in says why without keeping the rest of the address.<br>**A person's pace.** One request at a time per connection, a fixed 10 s rest after each reply (`PACE_SECS`, never randomised), and a daily limit: 50 by default, 1 to 1,000 (schema v26, `providers.web_daily_limit`), counted from the ledger since 00:00 UTC without Pygg's own 429 refusals. At the limit the gateway gets 429 `daily_limit` with Retry-After, and nothing reaches the site (test `the_daily_limit_refuses_before_the_site_is_touched`).<br>**No disguise.** Pygg never changes a window's browser fingerprint (user agent, client hints, canvas, fonts and the like). It never solves, skips or hides from a CAPTCHA, a sign-in page or a bot check: such a check stops the connection and tells the user to deal with it in the window.<br>**Debugging.** DevTools (a remote-debugging port, 9462) and a log of each navigation decision exist only in debug builds (`cfg!(debug_assertions)`), and only with `PYGG_WEB_DEVTOOLS` set. The log prints each address in full to the console, nothing from the page. Release builds have neither.<br>**Kept apart from Pygg.** The window has no Tauri capability, so the site cannot call Pygg's commands. The gateway reaches it through a loopback endpoint on a random port, behind a token that exists only in memory. Errors and the stored sign-in state are Pygg's own wording, never the page's text; the ledger, diagnostics and exports never name the profile folder.<br>**Lifecycle.** Each connection needs the user's acknowledgement of the account risk and starts off; it refuses tools, is never chosen by `auto` and records an unknown cost. Removing the connection closes its window and deletes its folder; a folder still held is deleted at the next start, before any window opens.<br>Verified by the 30 tests in `websession/tests.rs` with a scripted page (passed 2026-11-13), and live against the five sites on 2026-11-12 and 2026-11-13 ([PROVIDERS.md](PROVIDERS.md#web-session-unofficial)) | `websession/mod.rs`, `websession/window.rs`, `gateway/store.rs`, `commands.rs` |

## What the user is trusted with

- **Checks run code.** An approved check runs the code an agent wrote, on this computer, with the user's rights. Detected checks are only suggestions until approved.
- **Agents can run commands** where their own tools allow it; Pygg gives them file tools by default, and shell only when the user allows it (Claude Code's Bash, Gemini's yolo mode). Codex keeps its own sandbox.
- **The data folder** holds prompts, ledger entries and agent output, and each web session's profile folder with its sign-in. It is the user's to protect, like any other local file.
- **A web session's window is a browser while the user signs in.** Whatever the user opens there in that time is kept in that connection's profile folder, as a browser would keep it.
- **A web session acts as the user on the site.** Its terms may forbid automated use, and the account can be limited or banned; the user accepts this per connection (ADR-035). For an agent like Muse, what a client sends through Pygg is sent from the user's account, though Pygg denies every action the agent asks to take.
- **`SMARTTASKROUTER_CAPTURE_DIR`**, a debugging aid, writes translated streams (whole model answers) to that folder. Leave it unset except when diagnosing.

## Not covered yet

- Signed builds and a signed updater (ROADMAP D3, D4).
- A security review of the agent CLIs themselves, which Pygg runs but does not control.
- Multi-user or remote use: Pygg assumes one user on one machine.
