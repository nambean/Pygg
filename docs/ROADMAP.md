# Pygg — Authoritative Product & Delivery Roadmap

> **Status:** Authoritative · delivery order and gates · reviewed 2026-11-11

> v1.0 · 2026-11-11 · This file is the **single source of truth for global implementation priority**, superseding phase numbering in design/RFC documents. Always consult [Implementation Status](IMPLEMENTATION-STATUS.md) for what actually runs. Nothing marked Planned here is a code-delivery claim.
>
> **North star:** AI Cost Optimizer for everyday AI users *and* developers: automatically choose an eligible provider/model/account, preserve user experience and context, and minimize **quality-adjusted total cost per successful answer/task**, not nominal token price. **Initial measured market wedge:** API-heavy developers using multiple authorized providers/agent CLIs, because pay-per-use ROI and task verification can be benchmarked. Everyday users are reached through the clients they already use, pointed at the gateway; the app hosts no chat of its own (ADR-028).

## Current built foundation (as reported by Implementation Status, not independently rerun here)

A local Rust gateway at `127.0.0.1:8741` with OpenAI Chat Completions, Anthropic Messages and OpenAI Responses surfaces (native passthrough where the formats match, translation elsewhere; Responses since 2026-11-12, ADR-033, so Codex CLI can use any connection), 26 provider presets and 6 local runtimes plus custom OpenAI- and Anthropic-compatible endpoints for providers outside the list, combos with error-scoped fallback, client tokens with limits, a cost-provenance ledger, `auto` routing, a headless `gateway serve`, and desktop Overview/Connections/Combos/Clients/Usage, Agents, Tasks, Workspaces and Settings screens. On top of it: official agent CLIs run with their own sign-in (ADR-026), task engine v1 with checks and a cascade across agent steps, and tasks started from IDE agents through MCP (ADR-027). Live verification: Gemini (routing, fallback, ledger), Anthropic (native passthrough, with cache parity measured direct versus gateway on claude-haiku-4-5, claude-haiku-5-5 and claude-sonnet-5-5, the 1-hour TTL and a tool round trip), Qwen's token plan, real error answers from 8 providers, OpenCode, and a headless Claude Code session (session header on every request). No claim of parity for OpenRouter's cache, Anthropic-compatible third parties, or an interactive Claude Code session. Client tokens can be restricted to named connections; a server error does not move to another model unless the client allows it; only one gateway serves a store at a time. Rule-based `auto` and `auto/cheap` exist and were tried live on Gemini, Anthropic and Claude Code; they make no savings claim until the optimization benchmark has run. [Implementation Status](IMPLEMENTATION-STATUS.md) is authoritative, including the verification level of each P0 item.

> **Independent counter-review (2026-11-11):** [Architect counter-review](reviews/2026-11-11-architect-counter-review.md) challenges error/quota scope, budget guarantee, accounting durability, Retry-After HTTP-date, HTTP 408/409/425 retry, session isolation and native Anthropic parity. **Answered item by item** in the [counter-review response](reviews/2026-11-11-counter-review-response.md): six accepted, three in part, with the code and tests that implement them. Since then P0-1 has measured cache parity on three Anthropic models (C1), and P0-4 a headless Claude Code run; see the status table below.

> **Follow-up review (2026-11-11):** [Remaining Gateway Risks](reviews/2026-11-11-remaining-gateway-risks.md) requests Claude's response on per-client privacy-safe fallback, paid retry exposure after 5xx, SQLite fault-injection/accounting-degraded behavior, and documentation updates following real Anthropic/Claude Code tests. **Answered** in the [follow-up response](reviews/2026-11-11-remaining-gateway-risks-response.md): all four accepted. Client tokens can be restricted to named connections, paid retries after a server error are off by default, and no paid request is admitted while a ledger entry waits to be written. Provider data-use terms (GW-10) were built later (B2); provider-side usage reconciliation is deferred. Check [Implementation Status](IMPLEMENTATION-STATUS.md) for the latest parity evidence.

> **Post-`d518438` engineering review (2026-11-11):** [Cross-process accounting and Free/Local replay safety](reviews/2026-11-11-post-d518438-counter-review.md) challenges process-local degraded-ledger admission and the assumption that Free/Local 5xx requests are automatically replay-safe. Requests a documented singleton-or-multi-process contract and tests. **Answered** in the [post-d518438 response](reviews/2026-11-11-post-d518438-response.md): one gateway per store, enforced by an OS file lock and tested with two real processes; a 5xx stops on every billing type unless the client opts in.

> **Gateway lifecycle follow-up (2026-11-11):** [Stop/start ownership and journal-recovery counter-review](reviews/2026-11-11-gateway-lifecycle-counter-review.md) raises four review findings: per-gateway ownership epochs, detached/streaming work outliving the file lock, ignored startup recovery errors and missing same-process restart tests. **Answered** in the [lifecycle response](reviews/2026-11-11-gateway-lifecycle-response.md): all four accepted. The store's ownership is held by the server, every attempt in flight and every waiting settlement, and released only when the last one is settled. Ownership generations replace the process timestamp. A failed start-up recovery fails the start. Five lifecycle tests cover the review's matrix.

### P0 release proof: benchmark, not a sixth feature

- **Parity baseline:** exact same model/provider direct vs proxy with at least two turns that exercise prompt caching, tools and streaming; cache savings and total billed amount cannot regress materially without explicit explanation.
- **Optimization baseline:** pinned premium vs pinned inexpensive capable vs static combo vs rule-based Auto, with success/quality checks and standardized prompts.
- **Accounting:** include cache write/read, retries, request cancellation, classifier (if any), extraction, time spent verifying/reworking, unknown costs and client overhead.
- **Honesty gate:** do **not** promise percent cost savings or automatic quality retention without a reproducible benchmark and confidence bounds.
- **Security gate:** no unauthorized account/key switches, no denied provider terms/data-use, no budget overrun via concurrency.

## P1: continuity + measured optimization (after P0 gate)

1. **Agent CLIs as executors (started 2026-11-11, owner decision):** Claude Code, Codex CLI, Gemini CLI and OpenCode run with their own sign-in in a Git worktree per task; Pygg never reads or forwards that sign-in, and never bridges web sessions or other products' OAuth. Built: detection, a run with diff, keep as branch or discard, and ledger entries; task engine v1 with approved checks, a cascade across agent steps, approval before a paid step, stop and recovery after a restart. Owner decision (2026-11-11): tasks are started from where users already work, by their IDE agent through `pygg-mcp` and the gateway's task API; the app runs them and is where they are watched and paid steps approved. Built, and verified from real Codex and Claude Code sessions; the app's own program serves MCP (`<app> mcp`), so the installer ships nothing extra. See [AGENTS.md](AGENTS.md#from-the-ide-pygg-mcp-and-the-task-api).
1. **Developer integrations:** verify Claude Code, OpenCode, Aider, Codex and IDE targets one by one with test fixtures; maintain exact version/capability matrix. Package a headless CLI installer/npm launcher after supported OS builds, without cloning the Rust gateway in Node. Current CLI binary is `gateway serve`; `str start` is a proposed future interface.
2. ~~**Owned Auto Chat**~~: withdrawn (ADR-028, no Auto Chat in the app). **External client-managed chat stays opaque**: no context injected or reconstructed.
3. **Cache-aware route scoring:** account/model affinity, measured cache read/write, cost to rebuild and quality consequences. Prefer staying when switching adds cost.
4. **Token reduction:** (**shadow measurement built 2026-11-12**, schema v21: each request's repeated tool output is counted, never removed, and Usage → Repeated Tool Output weighs it against input and cache reads; nothing is changed until those figures justify an opt-in) only deterministic, reversible dedup/noisy new tool-output filtering in **shadow and opt-in** first; verify prefix hash/cache parity before enabling defaults. Never silently rewrite external agent history.
5. **Benchmarks and quality feedback:** measured cost per accepted result, failures, user revisions and manual time estimates. LLM classifiers only with a strict input/cost budget and only at explicit classification boundaries.

## Revised plan after ADR-026 and ADR-027 (2026-11-11 docs review)

A review of every planning doc against the build ([DECISIONS](DECISIONS.md), the [functional plan](SMARTROUTER_UI_UX_FUNCTIONAL_PLAN.md), [SCREENS](design/SCREENS.md), [Account Rotation](ACCOUNT_API_ROTATION.md), [CLI/IDE/npm/Tiers](CLI_IDE_NPM_PROVIDER_TIERS.md), [Universal Memory](UNIVERSAL_SHARED_MEMORY.md), the [OmniRoute research](OMNIROUTE_FEATURE_RESEARCH.md), the [benchmark README](../benchmark/README.md), the root README and every file in [reviews](reviews)). In order:

**A. Make the IDE flow usable every day**
1. **Built 2026-11-11:** tray and notifications for a paid step waiting, a task ready, needing review or not finished (SCREENS §2.5). Per ADR-010, no task names or paths, and no approve button, in a notification. Closing the window keeps the gateway and tasks running from the tray (review GW-9); both are switches in Settings → Background. Not yet: a click on a notification opening the task.
2. **Built 2026-11-11:** approvals as ADR-010 specifies (SCREENS §6.3). The estimate is the range of the agent's own list-price estimates over its last 10 runs of that model; approving needs a cap; Claude Code stops at it itself (`--max-budget-usd`), and for other agents a reported cost over the cap stops the ladder. An approval is invalidated and asked again when its estimate changed before the user decided. A budget change (A3) also invalidates it.
3. **Built 2026-11-11:** task budgets per day, overall and per workspace (functional plan §2.4; schema v11), for paid steps only. A finished paid step counts at the agent's own estimate, or at its cap when it reported none; a running one holds its cap. A used-up budget blocks a paid step before it asks; a cap cannot pass what is left; a budget change invalidates a waiting approval. Days are UTC. Set in Settings → Task budgets; the toolbar shows today's figures.
4. **Built 2026-11-11:** the Workspaces screen (SCREENS §5.3): each workspace's checks to approve (a sidebar badge counts workspaces whose suggested checks wait, as IDE-created ones do), its privacy class, its daily budget, and removal while it has no tasks; Add Workspace with the system's folder picker. In a **sensitive** workspace every step asks before an agent sees the code, free ones included: agents run with their own sign-in, outside the gateway, so data-use terms (B2) cannot say where they send it. The folder picker has not been clicked through in the native app.
5. **Built 2026-11-11:** Export Patch next to Keep as Branch (ADR-009): the result saved through the system's save dialog as a patch `git apply` takes (binary files included, a short header naming the task and its base commit); the result stays open to keep or discard.
6. **Done 2026-11-11:** Claude Code through MCP, verified like Codex (AGENTS.md).

**B. Gateway correctness**
1. **Built 2026-11-11:** `auto` filters by request features (schema v12). An Anthropic request's `thinking.type` (adaptive, enabled) and `output_config.effort` go only to native Anthropic targets known to take them; Anthropic's model list gives `capabilities.thinking.types` and `capabilities.effort` (read on refresh, overridable in Connections → Auto…); unknown counts as missing, with a reason saying how to fix it. Translated targets drop both and stay eligible. Checked against the live list (C1): `claude-haiku-4-5` takes neither adaptive thinking nor effort.
2. **Built 2026-11-11:** data-use terms per connection (review GW-10; schema v13): `no_training`, `may_train` or not recorded, with where the user read them and when; `no_training` needs a source. A client can require providers that do not train on its data, a hard filter on combos, fallbacks, session pins, `auto`, `count_tokens` and the model list; not recorded counts as may-train. Pygg does not fill terms in or check them. Smart tasks run agents with their own sign-in, outside the gateway, so a sensitive workspace keeps asking before every step.
3. **Built 2026-11-11:** Pygg's tier table (`gateway/tiers.rs`, source `curated:v1`), filling only tiers nobody set: each vendor's own naming of its line (Haiku, Flash-Lite, nano, mini, small at the small end; Sonnet, Flash, medium in the middle; Opus, Pro, large, reasoner at the top), local runtimes T0, unknown lines left unset. A tier the user sets or clears is never changed again; the capability sheet says why the table gave a tier, and `auto`'s reason says `from Pygg's table`. A starting point, not a measurement: the benchmark (C3) is what can correct it.
4. **Built 2026-11-11:** a circuit breaker and probe (Account Rotation §5; schema v14): an unreachable or failing connection waits twice as long with each failure in a row (up to 15 minutes), and while the gateway runs, an unreachable connection's free model list is read again every minute; when it answers, the outage is lifted. Rejected keys and quotas are not probed (a model list can answer without a key). A **strict** client limit holds each request at the most it could cost (its own output limit, or the model's maximum output) and never uses a model whose price or maximum output is unknown (Clients → Limits).
5. Translation gaps: ~~OpenAI → Anthropic~~ (**built 2026-11-11, N8**, verified live on Claude Haiku 5.5: plain, tool round trip, stream); ~~reasoning~~ (**complete in both directions 2026-11-12**: a provider's `reasoning_content` reaches Anthropic clients as signed `thinking` blocks, live on Qwen; `reasoning_effort` reaches Claude as `thinking` and Claude's thinking comes back as `reasoning_content`, live on Haiku 5.5 and 4.5; thinking signatures cannot travel in Chat Completions, so Claude thinks afresh each turn there).
6. Smaller deferred review items: ~~Gemini thought signatures kept across a restart (GW-8)~~ (built 2026-11-11, migration 0016); ~~a combo-editor warning for two connections of one provider (GW-1)~~ (built 2026-11-11: the editor names connections in a combo that share a quota group; not yet clicked through, the demo has no such pair); idempotency keys (CR-05). Held until an adapter can fill them: provider-verified organization and quota scope (CR-02), and reconciliation against the provider's own usage (FR-03). GW-7 (fallback before the first token) stays held.

## Product rules that override outdated speculative docs

- **Billing tier ≠ auth method ≠ capability tier.** Free/Subscription/API Paid/Local/Unknown are per account-model entitlements with provenance, not guaranteed provider-wide facts.
- **Do not automatically switch model within active agent attempt, tool call or partial stream.** Pinned external clients retain prompt ownership and cache semantics.
- **Prefer native passthrough over conversion.** Cross-format routes must pass streaming/tools/images/cache/citation contract tests and reveal feature loss.
- **No account cycling to evade bans, rate limits or provider terms.** Shared quota groups are hard constraints.
- **Do not count free subscription-window tokens as USD savings**; distinguish money, tokens, local operating costs and quality/human rework.
- **Cache-stable conversation prefix** is preserved within pinned epochs; compaction and handoff explicitly account for cache reset overhead.
- **Metrics should never manufacture precision:** unknown price/usage = Unknown; savings require valid baseline.
